## 用户如何描述问题(保留原文)

不用组织成设计语言。任意一种输入都可以:

- 截图圈一块,说"这里烦 / 挤 / 看不懂 / 不该在这 / 容易误触"。
- 说一句真实动作,例如"我想把这张歌单离线,但不知道点哪个"。
- 只给结果感受,例如"我不知道它有没有开始下载"。

会翻译成:任务流、状态反馈、信息层级、控件位置、视觉一致性五类问题。

## 已落地

### 1. 统一保存语义 ✅
- 歌曲行主位置只保留「播放 / 收藏 / 更多操作」,保存类动作进菜单。
- 菜单文案直接写清后果:「存到服务器 —— 长期保存进 NAS 曲库,任何设备可听」
  vs「缓存到本机 —— 存进当前浏览器,可离线听」。
- 已保存状态用文字徽章(`服务器` / `本机`)表达,不再只靠按钮变勾。
- 「我喜欢」歌单没有删除歌单按钮(`canDeleteCollection` 排除 `kind=favorite`)。

### 2. 搜索页降低技术感 ✅
- 状态表达分级:只有阻断性错误用带边框 banner;成功/进行中降级为一行内联灰字。
  "正在验活并过滤" 这类说法已随自动验活移除而废弃。
- 排序从三张等宽大卡片改为紧凑分段控件(推荐 / 高音质 / 小文件)。
- 顶部全局搜索与页面搜索共用同一入口逻辑(`requestDownloadSearch` → 回填并搜索)。

### 3. 危险动作与失败动作不静默 ✅
- 已下载页删除服务器文件:二次确认 + 失败提示 + 乐观回滚。
- 歌曲行下载/验活/缓存/收藏失败:全部经 `feedback` 给出可读原因(此前静默 `console.warn`)。
- 原生 `window.confirm` / `alert` / `prompt` 已清零(门禁禁止新增)。

### 4. 导航改成音乐任务模型 ✅(移动端)
- 移动主 Tab:首页 / 找歌 / 曲库 / 离线 / 更多。设置不再占主入口。
- 桌面侧栏按「发现 / 找歌 / 曲库 / 更多 / 我的歌单」分组。

### 5. 歌单页更像可操作的音乐集合 ✅
- 头图与标题层级统一(`PageHeader`);推荐歌单与自建歌单按钮语义一致。
- 空歌单直接给「去找歌」按钮,不再只提示"去搜索里点 +"。

### 6. 离线能力说清楚边界 ✅
- 离线页明确展示:本机缓存首数、音频体积、站点占用、持久保存状态。
- 浏览器未授予持久保存时给出可理解提示。
- 清空缓存前有确认。

### 7. 移动端播放器不遮挡 / 不误触 ✅
- 底部留白按「是否播放 / 是否提示 / 断点 / safe-area」动态计算(`index.css` 的 `.app-main--*`)。
- 所有可点区域 ≥ 44px(`min-h-touch` / `min-w-touch`)。
- 移动「更多」抽屉补 role/aria-modal、关闭按钮、Esc、滚动锁。

### 8. 视觉系统收口 ✅
- 去掉旧 `shadow-brutal*` 残留与硬编码色值(门禁禁止新增裸 hex / 任意色值)。
- 按钮、卡片、行高、间距统一到 `src/ui/`。
- 状态色收为语义:primary(唯一主动作)/ success / warning / info / destructive / muted。
  绿色不再被同时用于"成功、无损、VIP、选中态"。
- z-index 收为语义层(nav/tabbar/bar/popover/drawer/sheet/modal/toast),门禁禁止魔法数字。
- 滚动条统一 `.scroll-area` / `.scroll-x`(门禁强制),横向轮播改箭头 + 渐隐。
- 声明了但不存在的 "Roboto" 已移除,改系统字体栈;`color-scheme: dark` 让原生控件走暗色。

### 9. 额外补上的(原计划未列)
- **ErrorBoundary**:此前任意组件渲染异常 = 整页白屏。
- **无障碍**:Toast 补 `aria-live`;所有浮层有 `role="dialog"` / Esc / 焦点陷阱 / 焦点回归 / 滚动锁;
  全局 `:focus-visible` 焦点环;跳过链接;搜索建议支持 ↑↓/Enter。
- **reduced-motion**:从只覆盖 3 个加载动画扩到黑胶/跑马灯/滑入/平滑滚动。
- **前端 CI**:`verify` 现在对 `frontend/**` 变更跑 build + UX 门禁 + 全部契约测试
  (此前 CI 对前端完全不设防)。

## 已否决

- **"所有滚动条都隐藏"**:桌面鼠标环境没有滚轮横向惯性时,完全无法发现可滚动。已改为
  `.scroll-area` 细滚动条 + 横向容器隐藏槽但给箭头。
- **引入网络字体(Inter / 思源黑体)**:PWA + 离线 + 国内网络三重约束下是负收益,
  且"没有排版"的主因是字号/字重层级缺失,不是字体本身。
- **换掉 Spotify 绿**(改冷青/琥珀/紫):问题不在绿色本身,而在它被用于所有东西导致失去重点。
  改成"语义分离"即可,换品牌色是收益主观、返工成本高的方向。
- **全站全量迁移 40+ 组件**:改为高频主路径 + 全部 modal 迁移,低频管理页只做 token 替换,
  避免一次性制造过大回归面。
- **长任务"取消防抖/虚拟化"一刀切**:未做,见下方待办(需要真机数据支撑收益)。

## 一致性门禁(改 UI 前必读)

`npm run test:ux` 会拒绝以下回归(命中即 CI 失败):

| 规则 | 原因 |
|---|---|
| 裸 hex 色值 / Tailwind 任意色值 | 绕过 token,主题无法统一 |
| `z-[数字]` / `z-10..z-100` | 曾出现 15 个魔法数字与真实叠层冲突 |
| `window.confirm/alert/prompt` | 阻塞浏览器、无 Esc、样式与全站无关 |
| 可滚容器未挂 `.scroll-area` / `.scroll-x` | 会渲染成浏览器默认滚动条(白槽) |
| 图标按钮无 `aria-label`/`title` | 读屏为空 |
| `style={{ color/fontSize/... }}` | 绕过 token |
| UI 层 catch 只有 `console` | 用户主动操作失败却完全不可见 |
| — | 另外断言:App.js 有 ErrorBoundary、Toast 有 `aria-live`、不出现 `'N/A'` |
